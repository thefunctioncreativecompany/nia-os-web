## 1. The idea in one line

**One editor, 31 templates as data.** Every template in Figma is the same page: an editor on the left, a preview-and-export panel on the right, built from ten section types. Build the engine once; each template is an entry in `template-schemas.json`. A new template is a new entry, not a new screen.

## 3. Page anatomy (same for every template)

**Top bar:** back to Templates · breadcrumb `Templates / {name}` · save status (`All changes saved ✓ 16:16`).

**Editor (left):**
1. Group label (small mono caps), title (bold italic, as in Figma), one-line description. Builders with nothing added show *"Start building your {name} by adding sections below."*
2. **Toolbar:** Undo · Redo · the template's `actions` (Add Section / Add Block, Add Row / Add Line Item, Send to Crew, Mark Paid, Print). A heavy rule under the toolbar.
3. **Sections** in order, each with a heading. Optional sections have "Remove section".
4. **Add sections palette** (builders only): a grid of cards for sections not yet added, each with title, hint and "+ Add".

**Preview panel (right, sticky):** `PREVIEW` + status chip (`Draft` → `Ready to Export` once any section has content) · paper thumbnail that fills in as sections get content · template name, description, **contents** bullets · "N / M sections filled" checklist · **Download PDF** · **Save** · `Generated by Nia · {version}`.

## 4. Section types

| Type | Renders | Data shape (stored in `data[i]`) | Behaviour |
|---|---|---|---|
| `fields` | Grid of labelled single-line inputs | `{ [label]: string }` | — |
| `table` | Editable table | `[{ id, [column]: value }]` | Add row, remove row. Options: `autonumber` (read-only 01, 02…), `computed` (e.g. Extended = Rate × QTY), `money` columns, `total` row, `checkbox` columns, `tall` (multi-line cells), `empty` message |
| `text` | Multi-line box | `string` | Placeholder from schema |
| `letter` | Long text pre-filled with a template body | `string` | Counts as filled only once edited |
| `categories` | Grid of small labelled note cards | `{ [category]: string }` | Script breakdown categories |
| `frames` | N image panels (16:9) with a note under each | `[{ img, note }]` | Click to upload; store images in Supabase Storage, keep the path in `img` |
| `checklist` | Groups of checkboxes | `[{ label, items: [{ id, text, done }] }]` | Add item per group |
| `cards` | Repeatable cards: name, status chip, description, extra fields | `[{ id, name, status, desc, fields }]` | Status cycles Open → Shortlisted → Confirmed |
| `budget` | Grouped cost tables + summary | `[{ label, rows: [{ id, cat, desc, rate, units }] }]` | Subtotal per row and group; summary with contingency % and grand total |
| `metrics` | Large stat inputs | `{ [metric]: string }` | — |

Copy the behaviour from the prototype's `FieldsSec`, `TableSec`, `CategoriesSec`, `FramesSec`, `ChecklistSec`, `CardsSec`, `BudgetSec`, `MetricsSec` and the `initSection` / `sectionHasContent` helpers.

**Builder templates** (`builder: true`): every section has `optional: true` and a `hint`. A document stores `added: boolean[]`; only added sections render. Removing a section resets its data.

---

## 5. Behaviour rules

- **Undo / Redo:** typing within 0.7 s is one step; structural actions (add or remove a section, add a row from the toolbar, Mark Paid) are always their own step. Keep ~80 steps.
- **Autosave:** debounce 800 ms after the last change, then upsert to Supabase. Show `All changes saved ✓ hh:mm`, or `Saving…` / `Offline, retrying` when relevant.
- **Status:** `draft` until any section has content, then `ready`. Invoice adds `paid` (Mark Paid shows a PAID stamp).
- **Export:** v1 uses a print stylesheet so only the document prints (toolbar, palette and remove buttons hidden). A server-rendered PDF can come later.
- **Send to Crew** and **Save** need Cast & Crew and projects, so for now show a short message saying so.

## 6. Data (Supabase)

```sql
create table documents (
  id uuid primary key default gen_random_uuid(),
  project_id uuid references projects(id) on delete cascade,
  template_code text not null,          -- e.g. 'D01' (matches template-schemas.json)
  title text not null,
  data jsonb not null,                   -- one entry per section, shapes as in §4
  added jsonb not null,                  -- boolean per section (builders)
  status text not null default 'draft',  -- draft | ready | paid
  schema_version text not null,          -- template version when created, e.g. 'v2.4'
  created_by uuid references auth.users(id),
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
alter table documents enable row level security;
-- Policy: members of the project can select/insert/update; only the creator or project owner can delete.
```

Storage bucket `document-images` (private) for storyboard frames and any uploaded images; store the object path in the section data, never a data URL.

## 7. Code structure (Next.js, our tokens, shadcn primitives)

```
src/data/template-schemas.json
src/features/templates/engine/
  types.ts              ← TypeScript types for schemas and section data
  initSection.ts        ← blank data per section type
  hasContent.ts         ← "is this section filled?"
  useDocument.ts        ← state, undo/redo, autosave to Supabase
  TemplateEditor.tsx    ← header, toolbar, sections, add-sections palette
  PreviewPanel.tsx      ← status, thumbnail, contents, progress, export
  sections/Fields.tsx · Table.tsx · Text.tsx · Letter.tsx · Categories.tsx
           Frames.tsx · Checklist.tsx · Cards.tsx · Budget.tsx · Metrics.tsx
src/app/templates/[code]/page.tsx              ← open a template (new draft)
src/app/projects/[projectId]/documents/[docId]/page.tsx  ← reopen a saved document
```

Use shadcn's Input, Textarea, Table, Checkbox and Button underneath, styled with our token constants to match Figma.

## 8. Build order (one step at a time, show each running)

1. **Skeleton:** types, `useDocument`, `TemplateEditor` + `PreviewPanel` with `fields`, `text`, `letter`. Ship **Filming Notice**.
2. **Tables:** `table` with add/remove rows and autonumber. Ship **Crew Contact List, Shotlist, Equipment Rental Log, Continuity Log, Shot Logging Sheet** (checkbox column) and **3-Column AV Script** (tall cells).
3. **Computed tables:** totals and money. Ship **Invoice** (Add Line Item, Mark Paid).
4. **Call Sheet**, the most-used template: all its sections, plus Send to Crew stubbed.
5. **Categories and frames:** ship **Script Breakdown Sheet** and **Storyboard – 9 Frame** (uploads to Storage).
6. **Strategy types:** `checklist`, `cards`, `metrics`, `budget`. Ship **Content Production Guideline, Series Bible, Casting Deck, Press Junket Brief, Talent Roster Report, Production Budget**.
7. **Builders:** optional sections + palette. Ship **Call Sheet – Detailed** and the **13 UGC templates**.
8. **Save and reopen** documents in Supabase (§6), listed under each project.
9. **Print / PDF export.**
10. **Gallery wiring:** document templates in the gallery open `/templates/[code]`.

**Check each template:** opens from the gallery; matches its Figma `editor` frame; every section accepts input; rows add and remove; totals are right; Undo and Redo work; the preview turns `Ready to Export`; it prints cleanly; it saves and reopens.
